| A12 | 🐞 **BUG — `CreateAsset`, `CreateLocation`, `CreateHold` and `PostMovement` all honor a caller-supplied `id`, contradicting their own doc comments, and a duplicate id 500s instead of a clean conflict.** Driven through the real `routes.Routes(am)` mux (sqlite, in-process): `POST /assets {"id":"attacker-chosen-asset-id","name":"probe","tracking_mode":"fungible"}` → `201 {"id":"attacker-chosen-asset-id",...}` — the caller's literal string becomes the row's primary key, when `models/asset.go`'s own `ID` doc comment says "Set by the backend on creation; callers should leave it empty in create requests." `asset.go`'s `CreateAsset` never clears `a.ID` before `gormstore.AssetToRow(a)`, and `AssetRow.BeforeCreate` only mints a UUID `if r.ID == ""`. The identical gap, with the identical doc-comment contradiction, exists in `location.go`'s `CreateLocation`, `hold.go`'s `CreateHold`, and `movement.go`'s `PostMovement` — confirmed by the same probe against `POST /locations`, `POST /holds`, and `POST /movements`. Re-`POST`ing the same id a second time (`/assets` demonstrated) hits the sqlite/Postgres primary-key unique constraint and 500s (`errors.go` has no duplicate-id sentinel at all — no `ErrDuplicateID`/`ErrConflict` equivalent — so `writeAssetErr`'s default arm answers an opaque `500 {"error":"internal error"}`). Same bug class already found and fixed/pinned elsewhere in this fleet: `mwanachama-backend-agency`'s AG21, `mwanachama-backend-custody`'s DEV-1695/1696, and `mwanachama-backend-taskmanager`'s W11 (same integration-test sweep, same day) — this repo has neither the ID-clearing fix nor either sibling's duplicate-id classifier (`ErrDuplicateID` in actor, `ErrConflict` in comm/custody). **Fix location**: clear `.ID` at the top of `CreateAsset`/`CreateLocation`/`CreateHold`/`PostMovement`, before building the row; separately, add a duplicate-id sentinel (matching actor's `classifyDuplicateID`/comm's `classify` shape) and map it to 409 in `writeAssetErr`/the other three `write*Err` functions. | 📋 | Found 2026-09-16 by the fleet integration-test sweep (loophole catalogue #3/#9: a caller-controlled identity field the server's own docs say it should own).
